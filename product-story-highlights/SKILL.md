Build a `Get the highlights` style section that previews the page's strongest selling points before deeper feature chapters.

## Mandatory Preparation

Invoke `product-story-design` first. If context is missing, run `teach-product-story`.

Read `../product-story-design/references/product-page-patterns.md` and `../product-story-design/references/component-patterns.md`.

## Purpose

This section is a preview rail, not a spec dump.

It should:

- quickly establish the page's strongest reasons to care
- keep copy short
- let visuals lead
- help users see the shape of the story ahead

## Structure

Typical pieces:

- section title, often `Get the highlights.`
- optional lightweight CTA like `Watch the film`
- a set of highlight topics or chips
- one visual + one proof sentence per highlight

## Writing Rules

- Keep each highlight concept distinct.
- Keep each statement short enough to scan instantly.
- Use benefit-led phrasing, not internal feature names alone.
- Avoid long explanatory paragraphs.

## Visual Rules

- Each highlight should have one obvious visual anchor.
- Highlights should feel curated, not repetitive.
- Vary crop, scale, or framing so the rail does not feel templated.

## When To Use

Best for:

- flagship launches
- value launches
- creator devices
- performance wearables
- sensory experience products

Usually skip or simplify it for:

- accessory decision pages
- very short co-branded variant pages

## Quality Check

Before finishing, verify:

- the section previews the page without repeating it
- highlights are truly the strongest selling points
- users can grasp the product's appeal in seconds
